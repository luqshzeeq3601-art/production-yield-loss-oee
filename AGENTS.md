# AGENTS.md

## Project

**Production Yield Loss & OEE Early-Warning System**

Build a reproducible manufacturing analytics portfolio system:

`Raw data -> Python analytics/SPC -> PostgreSQL star schema -> Power BI -> measured impact`

Source of truth:

- `IMPLEMENTATION_PLAN.md`
- `Production Yield Loss and OEE Early.md`

Objectives:

- **O1 — Early warning:** reduce defect-to-alert latency by >=70%, target alert precision >=60%.
- **O2 — OEE + RCA:** decompose Availability x Performance x Quality and identify the top loss causes.
- **O3 — Automation:** replace manual Excel reporting with a Python -> PostgreSQL -> Power BI pipeline.

Never invent portfolio or resume metrics. Final numbers must be generated by the project.

# 2. Selective Routes

Before the first task tool call, declare:

```text
SELECTIVE ROUTE
mode: solo | delegate | audit | full
risk: <concise task-specific reason>
```

Use the recommended route in the task table below unless newly observed risk justifies escalation.

## `solo`

Use when risk is contained.

Flow:

`Sol/High -> implement -> test -> self-review -> accept`

Auxiliary agents: **none**

## `delegate`

Use when a complete, bounded specification can be handed to one implementer.

Flow:

`Sol/High architect -> Luna/Max OR Terra/High implementer -> Sol/High verifies -> accept`

No fresh reviewer.

## `audit`

Use when independent final scrutiny matters more than delegation.

Flow:

`Sol/High implements -> Sol/High verifies -> fresh Sol/High reviewer -> accept`

Reviewer is read-only.

## `full`

Use only for broad/high-risk work.

Flow:

`Sol/High architect -> Luna/Max OR Terra/High implementer -> Sol/High verifies -> fresh Sol/High reviewer -> accept`

Any fix after review invalidates the previous verdict and requires a fresh review.

# 3. Auxiliary Model Selection

Do not manually override model or reasoning on spawn. Use the Sol Advisor native roles.

| Lane | Model | Effort | Use |
|---|---|---:|---|
| Primary architect | GPT-5.6 Sol | High | All task planning, architecture, verification, acceptance |
| Routine implementer | GPT-5.6 Luna | Max | Bounded, fully specified, low-ambiguity implementation |
| Complex implementer | GPT-5.6 Terra | High | Judgment-heavy, statistical, high-risk, context-heavy, wide-blast-radius implementation |
| Fresh reviewer | GPT-5.6 Sol | High | `audit` / `full` review only |

### Exact native roles

```text
sol_advisor_luna_implementer
sol_advisor_terra_implementer
sol_advisor_sol_reviewer
```

Spawn auxiliaries with a fresh context:

```text
fork_turns: none
```

### Escalation

- Default to the recommended route.
- `solo` may escalate to `delegate`, `audit`, or `full` only when new risk is observed.
- Luna may escalate to Terra when implementation reveals:
  - material ambiguity;
  - unexpected cross-module impact;
  - statistical/methodological judgment;
  - high regression risk;
  - wide blast radius.
- Never silently downgrade a declared route.
- Never silently replace an unavailable model/role.

# 5. Reviewer Contract

Only use a fresh reviewer for `audit` or `full`.

Reviewer:

- model: Sol;
- effort: High;
- fresh context;
- read-only;
- never implements fixes.

Required result:

```text
SOL REVIEW
VERDICT: ship | fix-first | rethink
REASON: <evidence>
FINDINGS: <precise findings or none>
RESIDUAL RISK: <remaining risk or none>
```

If `fix-first`:

- `audit`: primary Sol fixes -> verifies -> new fresh reviewer.
- `full`: selected implementer fixes -> primary Sol verifies -> new fresh reviewer.

If `rethink`:

- return to architecture;
- do not report task complete.

# 6. General Engineering Rules

1. Execute **one task ID at a time**.
2. Read relevant code, tests, implementation plan, and interfaces first.
3. Make the smallest complete change.
4. Do not silently widen scope.
5. Use fixed seeds for sampling and simulation.
6. Do not commit `data/raw/`, `data/interim/`, secrets, or temporary Power BI backups.
7. Do not hard-code final impact or resume metrics.
8. Prevent train/test and Phase I/Phase II leakage.
9. Tests must validate behavior, not only execution.
10. A task is not complete until primary Sol reruns its verification.
11. Commit only accepted work.
12. Preserve unrelated user/concurrent edits.
